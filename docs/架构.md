## 入口加载机制

`index.js` 使用 `Promise.allSettled` 动态 import `apps/` 下所有 `.js` 文件，单个 app 加载失败不影响其他模块。导出 `{ apps }`，key 为文件名（不含 `.js`），value 为导出的 class。

## 分层职责

| 层 | 职责 |
|----|------|
| `apps/` | 命令注册、事件绑定、参数解析、回复用户 |
| `model/` | 数据访问：米游社 API 封装（`mys/`）、数据库操作（`db/`）、业务数据组装 |
| `model/base.js` | apps 层公共基类：`renderImg()`（调用 `Common.render`）、`screenData`（布局/资源路径） |
| `model/mys/BaseModel.js` | mys 层公共基类：实例缓存（in-memory + TTL，默认 10 分钟） |
| `model/db/BaseModel.js` | 数据库层公共基类：Sequelize 实例初始化、`initDB()` |
| `defSet/` | 配置模板（YAML），框架加载时读取 |
| `resources/` | 静态资源：HTML 模板（puppeteer 渲染）、图片、字体、前端脚本 |

## import 路径

- 同层：`./`（如 `./gachaData.js`）
- 同模块子目录：`./db/`、`./mys/`
- 框架模块：`../../../lib/`（如 `../../../lib/plugins/plugin.js`、`../../../lib/puppeteer/puppeteer.js`）
- 框架通用：`../../../lib/common/`（如 `../../../lib/common/common.js`）
- miao-plugin：`#miao` / `#miao.models`（通过根 `package.json` imports 字段）

## `e` 对象扩展模式

apps 层的 method 接收 `this.e`（即 `e`，Runtime 实例），在执行过程中会被逐步扩展：

| 属性 | 设置者 | 说明 |
|------|--------|------|
| `e.isSr` | 框架（消息前缀 `*` 触发） | 星铁模式，影响 roleId 查找、资源路径、game key |
| `e.game` | 各 app 根据上下文设置 | `"gs"` / `"sr"` / `"zzz"` |
| `e.uid` | `gsCfg.getMsgUid()` / `MysInfo.getUid()` | 游戏 UID |
| `e.roleId` | `gsCfg.getRole()` | 角色 ID |
| `e.roleName` | `gsCfg.getRole()` | 角色名称（别名） |
| `e.user` | `NoteUser.create(e)` | 当前 NoteUser 实例 |
| `e.ck` | `user.js` 绑定流程 | Cookie 字符串 |
| `e.noTips` | 各 model | 设为 true 跳过自动提示（如未绑定 uid 提示） |
| `e.mysSelfUid` | `dailyNote.js` 等 | 只使用绑定 CK 的 UID，不进入公共 CK 分配 |

## `accept()` 拦截模式

部分 app（如 `role.js`）实现 `accept()` 方法，该方法在**所有消息**处理前被调用。用于检测消息中是否包含角色名/别名，若命中则修改 `e.msg` 为标准命令格式，实现灵活的命令匹配。

## 关键类与单例

| 类/单例 | 文件 | 说明 |
|---------|------|------|
| `gsCfg` (单例) | `model/gsCfg.js` | 全局配置管理：`getdefSet()` / `getConfig()` / `getRole()` / chokidar 热重载 |
| `MysInfo` (静态类) | `model/mys/mysInfo.js` | 查询编排：`init()` → `getUid()` → `getCookie()` → `get()` → `checkCode()` |

| `ckRefresh` | `model/mys/ckRefresh.js` | CK 自动刷新：`tryRefreshCk()` 拦截 10001+login → stoken 换新 cookie 重试（互斥锁防并发、`_ckRefreshing` 防递归） |
| `DailyCache` | `model/mys/DailyCache.js` | Redis 按日分片存储，CK 分配池（ZSet）、KV/Hash 操作 |
| `PoolData` (静态类) | `model/poolData.js` | 卡池数据适配：301/302 取 miao-plugin `pool.js` 的 `poolDetail`（年份手误自动规范化），其余类型回退 `defSet/pool/<type>.yaml`；`getPoolCfg()` / `getNowPool()` |

## 配置系统

本项目不使用标准的三层配置（defSet + config.example + config.yaml），而是沿用的 Miao-Yunzai 模式：

- **`defSet/<app>/<name>.yaml`** — 配置模板（纳入 git）
- **`config/<app>.<name>.yaml`** — 运行时配置（.gitignore 忽略）

其中 `defSet/mys/set.yaml` 的 **`stokenPath`** 为 CK 自动刷新的 stoken 数据目录（默认 `plugins/Axiu-Plugin/data/stoken/`，可配置为任意插件的 stoken 目录）。

`defSet/pool/301.yaml`（原神角色限定池）与 `302.yaml`（武器限定池）自 2026-11 起**只作回退**：权威数据是 miao-plugin 的 `resources/meta-gs/info/pool.js`，经 `model/poolData.js` 适配；星铁 `11`/`12`、集录 `500`、常驻/新手与联动池仍以 YAML 为准。

`gsCfg` 通过 `getConfig(app, name)` 读取：以 `defSet` 为基础，`config` 中同名 key 覆盖。`getdefSet(app, name)` 只读模板。

注意 `ignore` 名单（`mys.pubCk`、`gacha.set`、`bot.help`、`role.name`）中的配置直接读 `config`，不合并 `defSet`。

`gsCfg.cpCfg(app, name)` 用于首次使用时从 `defSet` 复制配置到 `config/`（由各 app 的 `init()` 调用）。

所有配置文件通过 `chokidar` 监听，修改即时生效（修改后清除内存缓存，下次访问时重新读取）。
