# 上游同步

> 与官方 Miao-Yunzai 的关系、同步模型（无共同祖先 → 人工挑选增量）与冲突处理。

AxiuCN/genshin-plugin 与官方 Miao-Yunzai 的 `plugins/genshin` **提交历史无共同祖先**（AxiuCN 为独立建仓，根提交 `999f65b 新增文件`），且内容基线大面积分叉（实测：代码目录 83 文件、资源目录 333 文件与官方不同；官方 6.7 之后提交多只动资源数据）。因此**无法用 merge / diff-apply 做全量同步**，正确做法是**按官方提交批次人工挑选增量**——官方近期提交通常只有少数文件（如「更新7.0探索」仅 3 个文件：至冬图 + 角色索引），挑选成本低、风险可控。

## 仓库角色

| 仓库 | 角色 |
|------|------|
| 本机官方镜像仓库（路径见 `docs/private/`，不入库；remote `origin`=官方，本插件仓库的 `miao` remote 指向它） | 官方完整镜像源，**不做日常开发** |
| `AxiuCN/genshin-plugin`（本插件目录，remote `origin`=AxiuCN、`miao`=本地镜像） | 日常开发 + 同步主场 |

## 一次性初始化

```bash
# ① 镜像仓库：首次克隆官方（历史大，耗时数分钟）到本机镜像目录
git clone https://github.com/yoimiya-kokomi/Miao-Yunzai.git <镜像目录>
# ② 本插件仓库：接入本地镜像（此后官方更新直接从镜像 fetch，离线可用）
git remote add miao <镜像目录>
```

> 镜像内的 `genshin-only` 分支是早期同步遗留的过期影子（停在 `b085502`，不含官方最新也不含 AxiuCN 提交），**已弃用**（已在镜像中删除）；镜像目录的 `origin/main`（官方无用遗留分支）勿用。

## 每轮同步官方更新（本插件目录执行）

```bash
git fetch miao                                # 更新本地官方镜像引用
git log miao/master --oneline -5              # 看官方近期提交
# 定位目标增量区间（<prev> 上次已同步点, <target> 本次目标提交）：
git log <prev>..<target> --oneline -- plugins/genshin      # 区间内 gen shin 改动提交
git diff --stat <prev>..<target> -- plugins/genshin        # 改动文件与规模评估
# 逐个文件采用（人工挑选，见下）：
#   纯资源/数据（探索图、计数、池子）且 AxiuCN 未本地改 → 直接提取官方版：
#     git show miao/master:plugins/genshin/<path> > <path>   （注意二进制用 cmd 字节重定向）
#   代码文件 → 未本地改过 → 提取官方版；本地改过 → 按「冲突处理」合并
#   纯格式化/全量 lint 类提交 → 跳过（无功能价值且与自有代码风格冲突）
git add -A && git commit -m "sync: <中文描述>" && git push origin master
```

**为什么不能 merge / diff-apply 全量同步**（实测事实）：
- `git merge -Xsubtree miao/master` → `refusing to merge unrelated histories`（两仓库提交图零交集，`merge-base` 为空）；
- 强行 `--allow-unrelated-histories` → 419 文件逐文件对峙且每次全量重复，不可行；
- 试图用 "官方历史中的同步点" 做 `diff <点>..miao/master` 增量 → AxiuCN 与官方任何近期提交的内容基线都不一致（代码 83 / 资源 333 文件差异恒定），稳定增量点不存在。

## 冲突处理（仅采用代码文件且与自有改动重叠时）

- 重叠集中点（AxiuCN 本地改过、官方也在改）：`model/mys/mysApi.js`、`model/mys/mysInfo.js`、`model/user.js`、`apps/user.js`、`model/blueprint.js`、`model/calculator.js`、`model/ledger.js`、`defSet/mys/set.yaml`
- 决策规则（冲突文件）：
  - 两处改动互不相关但邻接 → 手动合并两边（参考官方版 + 自有挂点）
  - 官方改动正是你要的新功能、自有改动已过时 → 采用官方版
  - 保留自有改动 → 不采用官方该文件
- 资源/数据类文件（探索图、计数、池子）AxiuCN 通常未本地改 → 直接采用官方版，无冲突

## 注意

- 官方代码提交多为「更新探索」类（数据为主），实际增量很小；出现「格式化代码」（pnpm lint 全量）类提交时**跳过**，不纳入同步
- 官方默认分支是 `master`；镜像目录的 `origin/main` 与 `genshin-only` 均勿用
- 不要 push 镜像仓库的 `origin`（官方仓库，无权限也非自己的）

## 日常开发（本目录）

```bash
git pull origin master     # 拉取同步后的更新
# ...开发...
git push origin master
```
